# v4 任务工作区与导航设计记录

日期：2026-11-09。本文记录 v4 简约版的全部任务页、跨页选择、批量操作、导航与连接设置约定。用户操作入口见 [工作台指南](../console-guide.md)；v3 审批流程及其已有验收继续保留在 [审批验收记录](validation.md) 和 [API 文档](../console-api.md)。

## 1. 页面结构

全部任务页以任务列表为主体，上方保留状态切换、搜索及三个工具入口，下方呈现范围与分页。任务身份分为「名称」和「ID · 问题类型」两行，高或紧急优先级使用小箭头提示；仓库、分支和完整优先级放入标题与元数据的悬停信息。复选框、任务名称及行末菜单分别承担选择、查看与操作职责。

| 区域           | 职责                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| 状态快捷项     | 快速查看全部、运行中、待审批、失败、已完成；其余状态在详细筛选中提供             |
| 搜索与工具栏   | 搜索框配合「筛选」「显示」「导出」三个入口                                       |
| 筛选面板       | 按需展开状态、引擎、类型、优先级、来源、分支和独立创建时间范围                   |
| 显示面板       | 集中管理排序、舒适／紧凑行间距及辅助列可见性；创建时间表头仍可直接排序           |
| 已应用条件     | 关键词由输入框呈现，常用状态由选中项呈现；详细筛选使用可移除标签，并提供清除全部 |
| 选择栏         | 显示跨页选中数量，区分选择本页与选择全部筛选结果，提供批量入口                   |
| 任务表格       | 状态与任务信息保持可辨；辅助列支持隐藏，行间距支持舒适与紧凑                     |
| 分页           | 显示当前条目范围、总数、页码以及 10/20/50 条每页选项                             |
| 批量确认与结果 | 确认前呈现 eligible/skipped；执行后给出应用数量、跳过原因及重试新 ID             |

页面使用细分隔线、文字层级和留白组织内容，状态以小图标和文字呈现。密度调整改变行间距，辅助列开关改变信息展示范围；任务身份、状态、选择和操作入口始终保留。首页继续展示概览及审批流程，审批中心仍负责逐关决定。

## 2. 查询模型

[task-model.js](../../apps/console/public/task-model.js) 提供纯函数，接收当前任务快照，不访问网络、不执行命令，也不改变输入数组或任务记录。

| 接口                          | 约定                                                                                          |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `DEFAULT_TASK_FILTERS`        | 空关键词；状态、引擎、类型、优先级、来源、分支均为 `all`；`days: 0` 表示全部时间              |
| `getTaskDisplayStatus(entry)` | `reviewState === "pending"` 时返回 `review`，否则使用原始任务状态；仅影响展示                 |
| `getTaskList(tasks, options)` | 返回完整筛选排序结果 `filtered`、当前页 `items`、总数、页码、页大小、页数、显示范围和状态计数 |
| `getTaskFilterOptions(tasks)` | 返回去重且顺序确定的引擎、类型、优先级、来源、分支字符串数组；优先级按紧急、高、中、低排列    |

搜索只匹配任务标题、ID、仓库、分支和相关文件，忽略大小写并按字面量匹配，不使用正则表达式或搜索原始上下文。不同筛选条件取交集。触发来源使用 `task.metadata.triggeredBy` 的 `manual`、`webhook`、`cron`；`metadata.source` 是事件来源详情，不作为这个分类控件的数据。

时间使用任务创建时间和 `Asia/Shanghai` 日历边界，最近 N 天包含当天。未来或无法解析的创建时间不进入结果。全部任务默认不限制过去日期，支持今天、近 7/30/90 天，与首页时间范围分别保存。

状态计数在应用关键词、引擎、类型、优先级、来源、分支和时间后计算，再应用当前状态筛选。`counts` 包含 `all`、`review`、`running`、`pending`、`failed`、`completed`、`cancelled`、`skipped`；待审批与队列中互斥，不会重复计数。底层 `TaskStatus` 仍是原来的六种状态。

支持 `created-desc`、`created-asc`、`priority-desc`、`duration-desc`。相同排序值以 ID 升序稳定排列；未知耗时排在已知耗时之后。耗时优先取有效的 `result.timings.durationMs`，否则尝试使用有效起止时间差，不推算正在运行任务的剩余时间。

默认每页 10 项，只接受 10/20/50，其他输入回到 10。页码限定在有效范围；空结果返回第 1 页、共 1 页及 `start: 0`、`end: 0`。排序和分页均建立在完整筛选结果上。

## 3. 选择范围与显示偏好

选择使用稳定的 `task.id`，不依赖当前行号。表头复选框只作用于当前页，部分选中使用原生 `indeterminate`。扩大到所有页面需要明确使用「选择全部 N 项筛选结果」，批量栏持续显示选中总数。

| 用户操作或数据变化       | 选择行为         | 页码与其他状态                         |
| ------------------------ | ---------------- | -------------------------------------- |
| 翻页                     | 保留跨页选择     | 转到目标页，关闭行菜单                 |
| 改变排序或每页条数       | 保留选择         | 回到第一页                             |
| 改变行间距或辅助列       | 保留选择         | 保存显示偏好                           |
| 改变搜索、状态或其他筛选 | 清空选择并提示   | 回到第一页，清理旧批量结果             |
| 清除全部筛选             | 清空选择         | 恢复默认条件并回到第一页               |
| 刷新数据                 | 清空选择及旧确认 | 保留筛选，回到第一页；演示快照本身保留 |
| 切换演示／真实数据源     | 清空选择及旧确认 | 恢复默认筛选，回到第一页               |
| 任务不再存在             | 剔除失效 ID      | 页码按新结果范围修正                   |
| 批量操作完成             | 清空选择         | 展示本次逐项结果，按新任务集合修正页码 |

每页条数、舒适／紧凑行间距、执行引擎／耗时／创建时间三列的可见性保存在本地显示偏好中。排序入口与这些显示项放在同一面板，但排序仍只属于当前页面会话；搜索和筛选也不持久化。这些偏好不保存任务数据、操作授权或选中 ID。窄屏优先呈现任务与状态，不靠缩小正文挤入全部辅助列。

## 4. 批量操作与结果语义

`planBulkAction(snapshot, { type, ids })` 只接受 `cancel` 和 `retry`。`ids` 必须是明确的 ID 数组；重复项去重，空或缺失选择不会退化为全量操作。不支持的类型直接拒绝，包括审批命令。

所有写操作同时要求 `snapshot.mode === "demo"` 和 `snapshot.capabilities[type] === true`。只把字符串 ID 对应的当前任务纳入判定；不存在的 ID 进入 `skipped` 并给出原因。

| 类型     | `eligible` 条件                                                             | 应用结果                                                                                                                          |
| -------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `cancel` | 原始 `status.status` 为 `pending` 或 `running`，包括待审批的 `pending` 任务 | 原任务变为 `cancelled`；审批流程冻结，已有验证证据、已决定关卡和取消记录保留                                                      |
| `retry`  | 原始 `status.status` 为 `failed` 或 `cancelled`                             | 为每项建立新 ID 的 `pending` 任务，设置 `context.retryOf` 并增加 `retryCount`；原任务及原证据保留，新任务不继承成功结果或审批授权 |

计划返回 `{type, requestedIds, eligible, skipped, canExecute, reason}`。`eligible` 是当前可处理任务的 `{id, title}` 列表；`skipped` 的每项还包含原因。状态不匹配、记录不存在、真实只读模式或 capability 未开放都会阻止相应任务进入可处理列表。选中总数与可处理数可以不同；没有可处理项时禁用确认入口。

确认框展示将处理与将跳过的任务。控制器在确认前重新生成计划；范围或原因变化时显示更新后的列表，要求重新确认。`applyDemoBulkAction` 执行时仍会重新检查资格，并通过现有 `applyDemoAction` 逐项生成新快照，因此保留单任务取消、重试和审批历史的既有行为。

结果为 `{snapshot, report}`，其中 `report` 包含操作类型、去重后的请求数量 `requested`、成功应用列表 `applied` 和跳过列表 `skipped`。重试成功项附带 `newId`。跳过表示该项没有被本次操作修改，不等同于把任务状态改为 `skipped`。零项应用时保留原快照，结果区明确显示没有任务被修改。结果明细可打开原任务或新重试任务。

批量取消、重试不会调用真实执行器、仓库、CI 或持久化审计服务。没有批量批准入口；v3 的 `code-review` 和 `execution-auth` 必须按顺序处理，所有节点证据和轮次检查继续生效。

## 5. 导出契约

工具栏「导出」使用 `getTaskList(...).filtered`，包含全部页面的筛选结果；「导出选中」使用明确选中的 ID。CSV 文件名标记数据源和选择范围，例如 `heal-tasks-demo-filtered.csv`、`heal-tasks-demo-selected.csv`。导出不修改任务，不要求写操作 capability；真实模式有可读取记录时也可以导出其摘要。

导出固定包含 11 个字段：`id`、`title`、`type`、显示 `status`、`priority`、`engine`、触发 `source`、`repo`、`branch`、`createdAt`、`duration`。其中时间保持来源字符串，耗时为毫秒，未知耗时在 CSV 中为空。字段范围独立于界面的辅助列开关。

CSV 使用 UTF-8 BOM、中文表头、CRLF 行分隔和双引号转义。以 `=`、`+`、`-`、`@` 开头的公式形态文本，包括前置空白、控制字符或格式字符，都会加前置单引号以避免按公式解释。导出显式投影字段，不序列化原始 payload、context、logs、evidence、配置或完整快照。

模型还提供 `exportTasksJSON(tasks, {mode, now})`，返回 `{mode, exportedAt, tasks}`，任务字段使用相同白名单。当前任务页下载入口使用 CSV；这个 JSON 辅助函数不是新的网络 API。

## 6. 导航与连接设置

侧栏按 `heal` 标识、概览／任务／审批／活动、分隔线、引擎／规则／策略组织；底部是设置入口以及主题、收起两个图标按钮。桌面支持收起成图标导航并保存偏好；当前页、悬停和键盘焦点分别呈现。审批项在有待办时显示数量。

顶部保留项目与当前页面位置，并用单一连接标识区分演示、只读、异常和加载中。点击标识进入设置。任务页使用自身搜索框，其他页面保留搜索图标入口；页面主体直接呈现当前内容与必要操作。

窄屏导航使用可关闭抽屉，支持关闭按钮、遮罩和 Escape；打开时限制背景交互，并管理抽屉内的键盘焦点。任务页菜单和显示面板支持退出后恢复焦点，原生批量对话框用于承载确认范围。

连接设置使用一张最大宽度 800px 的「数据来源」卡片。卡片内按来源切换、状态详情、能力摘要和可展开技术信息排列：

| 部分           | 内容                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| 来源切换       | 「交互演示／会话内模拟」与「管理服务／同源只读配置」                                |
| 状态详情       | 项目、分支、连接状态、最近读取时间；读取时间标记 UTC+8                              |
| 能力摘要       | 演示操作或配置读取的可用性，以及真实执行未接入                                      |
| 刷新与错误     | 可用时在卡片标题旁刷新；异常时就地显示完整转义错误和重新连接入口                    |
| 原生 `details` | 「接入与接口信息」默认收起，包含启动命令、默认地址、快照接口、配置来源和 `501` 合同 |

这种组织让日常来源切换与连接状态保持可见，技术接入信息在需要时展开。
