# v3：带审批流的自愈工作台

用户否定 v2 的过度素净，要求更接近所给设计平台，增加图标、特效和审批流。本轮是同一工作台的视觉和交互重做，沿用 PR #1 与既有只读网关。

## 方向与取舍

继续平面列表无法解决用户反馈；全屏霓虹和重玻璃会影响 diff 阅读。采用蓝灰背景、较实的白玻璃面板、细边缘高光、柔和双层阴影，以及蓝/青/紫图标底座。主要参考 Solid Glass 的材质与状态反馈、AffectUI Approval Gates 和 Agent Graph 的信息组织，独立实现，不复制付费组件。

首页突出修复流程与当前审批，统计使用轻量横向摘要，紧凑任务列表在下方。左侧导航新增审批中心，选中态有蓝色底光。重要图标尺寸20–24px；标题约26px，正文13px。支持浅深色与窄屏。

## 审批行为

流程为方案→质量/安全检查并行→代码审阅→执行授权→等待执行。每个节点可查看详情。两个手动关卡串行，第一关通过不能代表整个请求通过；最终批准仍停留在 pending，明确等待未接入的执行器。拒绝要求原因、阻塞后续节点并保留历史；重新发起新一轮要填写说明且保留上一轮记录。

审批演示只作用于 demo 数据。真实模式不构造检查成功或审批记录，所有写能力保持关闭。沿用原 TaskStatus，用 approvalFlow 扩展表现多关审批。旧按钮不能跳过关卡；模型校验当前节点与轮次防止重复或过期操作。

## 动效

按钮按压、面板hover边缘高光、页签状态切换、当前审批节点呼吸、状态连线推进与历史更新。循环运动只用于明确的当前状态；prefers-reduced-motion 下停止非必要动画。文字和diff所在表面保持实底可读。

## 验收

检验两个关卡推进、拒绝原因、历史、重发、旧节点/轮次、取消、live隔离与XSS。浏览器验证首页和审批中心、节点详情、两个批准动作、拒绝/重发、深色与390px。产出实际页面截图并更新同一预览与Draft PR。
