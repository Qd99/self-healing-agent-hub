# 工作台版式重构 v6

## 目标

用户持续反馈页面杂乱、排版不好看。本次重构工作台、全部任务、监控面板与操作记录的信息层级及交互反馈，直接应用到已有 Site；保持原有任务、审批、监控和配置能力。

## 当前问题

首页给单条审批的大流程图分配了主要首屏，任务列表被推到下方；同一审批又出现在列表和大卡片中。彩色图标容器、细小文字、重复标题和边框令页面缺少焦点。

## 方案比较

1. **任务优先（采用，依最终反馈完善）**：带语义图标的紧凑统计卡、宽任务列表和辅助栏。符合日常处理任务的目的，延续现有行为。
2. 审批收件箱：适合审批量很大的场景，当前任务类型较多，不宜让整个首页只围绕审批。
3. 指标控制台：适合真实监控接入后；当前 Grafana 尚未连接，不能以虚构图表填充首页。

用户已授权修改当前 Site，本轮沿已有简约偏好执行，无需新建产品或更换技术栈。

## 设计决定

- 白色主画布、浅灰导航、石墨色主要按钮；蓝色用于交互强调和运行状态，绿/橙/红保留状态语义。
- 页头统一：标题左对齐；时间范围、刷新、发起巡检放在同一工具区。
- 首页删除大流程图及大审批卡，完整流程在审批中心保留。
- 四项统计使用统一 `uiMetric`：语义图标、轻量边框及清晰数字层级；图标颜色对应交互或状态，不使用立体高光。统计来自所选范围的任务快照，另提供按创建日期归组的完成／失败趋势。
- 主区为六条最近任务；标题 13–14px，元信息至少 11px，尾部状态与时间对齐。保留原 tabs 和交互 ID。
- 桌面辅助栏约 292px，用细分隔而非多个浮动卡片组织待审批、最近记录和引擎配置；不宣称真实健康状态。
- 全站导航、页头与控件使用现有 ui.js / ui.css；首页专用结构使用 home-* 作用域，避免旧样式竞争。
- 小屏统计 2×2，任务和辅助栏单列，标题允许换行。保留主题、侧栏折叠、手机抽屉、键盘和减少动画偏好。

## 约束与验证

不更改后端/数据契约、真实执行能力、Grafana 配置、审批阶段、任务批量操作和站点访问范围。检查实际浏览器桌面/手机/深色截图、任务与审批导航、时间筛选、全站代表性页面、构建与现有测试。交付可打开的 Site 和真实截图，代码同步现有 Draft PR。

## 本轮继续反馈：数据与交互质感

用户在发布前补充：首页需要图标和数据展示；全部任务、监控面板、操作记录也需同步优化，点击、按钮和边框必须有可感知反馈。沿用任务优先结构，追加以下设计：

- 统计以统一 uiMetric 组件呈现，增加有含义的图标和轻量边框；为首页补充基于当前任务快照的完成/失败趋势，标明按创建日期统计。
- 全站按钮、图标按钮、页签、筛选开关、可点击行与输入框有统一的 hover、pressed、selected、focus 和展开反馈。装饰性容器不伪装为可点击操作。
- 仅为交互表面增加轻微边框高亮、阴影和按压响应；尊重减少动画偏好，不使用持续闪烁或循环扫描光效。
- 手动刷新明确反馈成功/失败，真正异步操作保留 loading 状态；UI 动效不作为操作成功证据。
- 监控页面改善工具栏与未接入状态；未查询的指标仍显示缺失值，不能绘制虚构 Prometheus 数据。
- 任务与操作记录统一内容框架、行高、图标和选中态；既有筛选、选择、批量操作和导出语义保持不变。

## 最终实现与验证状态

四模块及统一交互已实现，完整 `npm test` 为 144/144 通过。浏览器复查修复了任务分页遮挡末尾行及「每页」标签换行；首页方向键切换、手机导航和原有业务控制保留。Site 继续使用演示模式，Grafana 连接与指标仍未验证。截图归档、代码同步与版本发布按实施计划收尾，详见 [v6 设计记录](../../design/console-v6.md)。
