# 管理台 v5：监控入口与统一组件

## 目标

延续 v4 清爽、克制的任务工作区，处理用户明确提出的四项问题：未来 Grafana 监控面板、操作记录与日志的区别、易懂导航、路由规则的可理解性。所有页面共用基础组件、颜色与间距。

## 设计选择

继续使用现有原生 ESM、CSS 和 SVG，不更换框架。导航使用完整且简短的中文名：工作台、全部任务、审批中心、监控面板、操作记录、执行引擎、路由规则、安全策略、连接设置。保留折叠与移动端抽屉。

监控入口采用「面板预览 / 接入配置」的同页结构。接入字段包括 Grafana 基础地址、仪表盘 UID、Prometheus 数据源 UID 与显示名称、明确列出的命名空间，以及可折叠的变量名称和组织 ID。首次接入展示未配置状态；格式校验通过仅表示配置完整，不声称服务连通。可导出配置和 Grafana 仪表盘 JSON；外链携带命名空间、数据源和时间范围。预览不查询真实指标、不制造在线状态，不自动加载第三方 iframe。未来经过部署权限与认证适配后可替换面板容器。

考虑过直接嵌入 iframe 和重新实现指标查询；前者依赖 Grafana 部署和授权方式，后者超出现有只读网关能力。本次由实现者选择外部 Grafana 打开与可用模板，保持配置、预览和真实运行状态可区分。

操作记录显示实际事件的操作者、动作、对象、时间，支持类别、时间和搜索，导出当前筛选结果。执行日志继续在任务详情内，不能把审计事件当成日志行，也不推断事件缺失的操作者或结果。

路由规则突出「满足条件 → 执行引擎与动作」。完整保留 retryCount 等条件，详情提供可读配置和折叠 JSON；启用状态不代表执行器在线。真实配置仍只读，演示开关须通过能力检查。

## 共用组件

ui.js 提供按钮、搜索、选择器、字段、状态、标签导航、空态；ui.css 为颜色、尺寸、圆角、焦点和深色主题的唯一 token 来源。任务、审批、概览、配置页面通过共用 helper 和 ui-* 类复用组件，业务布局保留已有结构，避免破坏筛选、批量操作和审批流。

## 边界

- 不合并 main，不改变原有真实执行接口的 501 行为。
- 浏览器配置保存为本机草稿，绝不声称已修改服务端或实际监听范围。
- 命名空间为显式集合；「全部命名空间」仅指该配置集合。
- 不在 UI 配置、快照和导出中放置 API token 或认证信息。
- 无已提供的真实 Grafana 地址、命名空间或 UID，示例值必须明显标注。

## 验证

模型测试覆盖不合法 URL、变量与 UID、命名空间范围、多值编码、配置白名单、筛选和导出；现有 72 项回归应保持通过。浏览器检查监控配置保存/校验/导出、事件筛选、规则详情和开关、任务与审批关键交互、深色和手机布局。更新同一私人预览和 Draft PR。
