# 工作台真实 API 接入实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 将当前 UI 连接到持久管理 API，并提供实际 Agent 任务领取、证据回传和执行结果接口。

**Architecture:** 同源 Node HTTP 服务，持久 JSON 事务存储，管理与 Worker 独立认证。现有 v1 展示协议扩展版本号与能力字段，UI 共享 API 客户端消费服务端快照。

**Tech Stack:** Node.js 18+ 内置模块、ES modules、现有原生浏览器 UI、node:test。

**Spec:** `docs/superpowers/specs/2026-11-10-live-api-design.md`

## Global Constraints

- 保留 v10 视觉与已有行为，不新增无关页面和依赖。
- 真实模式不使用演示状态写入，不自动生成成功数据。
- 不执行用户的生产修复、不合并 main、不更改私人 Site 访问范围。
- 单实例持久服务；缺少真实外部凭据时明确界定联调证据。

## Review Focus

- 过期审批、重复提交、并发取消和迟到 Worker 结果不能重复执行或覆盖新状态。
- 写文件失败、状态损坏及重启不得导致静默数据丢失。
- 请求体、响应投影、认证、CSRF 和 Worker 凭据不可串用或泄漏。
- 刷新失败与后台刷新必须保留用户正在编辑的表单和筛选。
- Grafana 校验必须限制出站目的地、拒绝重定向且不泄露令牌。

## 进度与决定

- 基线：`npm test` 180/180 通过；原功能分支工作区干净。
- 使用原 `feat/agent-console-ui` 专用功能分支继续工作，不创建重复仓库。用户已明确要求实施，按开发者授权规则直接推进。
- 不加入尚不存在的暂停/恢复 UI；实现现有取消/重试流程及运行中取消确认。

- 完成结果：274 项自动测试通过，类型检查与同源构建通过；真实浏览器验证创建、重启持久化、两级审批、Worker 回执、批量取消/重试、规则和监控保存。
- 独立前后端审查发现的路径隔离、结果校验、无代码方案和请求并发问题均已修复，并有先失败后通过的回归用例。
- 本地测试使用隔离数据和受控 Worker；没有连接用户的生产 Agent/Grafana，也没有向外部仓库执行修复。
