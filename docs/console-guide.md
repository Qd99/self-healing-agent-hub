# Web 工作台使用与设计说明

`heal` v7 收紧工作台、全部任务、监控面板与操作记录的信息密度：首页采用统一统计带、最近任务主区，以及审批和结果趋势辅助栏；各模块沿用语义图标、明确的操作入口和共用反馈。重复应用相同任务筛选条件会保留选择、页码与批量结果。原有分页、批量操作、两级审批及监控配置能力继续保留。当前实现包含可交互前端、同源只读配置网关和独立的内存演示数据；Site 仍为演示，具体 Agent 执行器尚未接入。设计、验证与交付结果见 [v7 记录](design/console-v7.md)，历史验收见 [v6 记录](design/console-v6.md)。

## 1. 本地运行

要求 Node.js 18 或更新版本。在仓库根目录运行：

```bash
npm run dev
```

默认访问 [http://127.0.0.1:8787/](http://127.0.0.1:8787/)。`npm start` 使用同一个入口。网关与前端静态资源由同一服务提供；当前启动过程使用 Node 内置模块，运行工作台本身不依赖 Redis、MySQL、GitHub App 或第三方模型凭据。

可通过环境变量调整端口：

```bash
PORT=8790 npm run dev
```

默认监听 `127.0.0.1`，`HOST` 可显式覆盖监听地址。当前没有登录或 RBAC；跨机器部署需要另行提供访问控制。

### 查看交互演示

打开 [http://127.0.0.1:8787/?demo=1](http://127.0.0.1:8787/?demo=1)，或进入「连接设置」选择「交互演示」。页面会明确标记演示模式。

演示初始化时包含 48 条虚构任务：42 条已完成、3 条失败、1 条运行中、2 条待审阅；任务时间根据打开页面的时间生成，覆盖最近七天。数据包含类型错误、Lint、单元测试、依赖与文档等场景，示例中的文件、提交、检查结果与日志均不代表真实仓库执行记录。

演示数据只保存在页面内存。同一页面切换数据来源后可继续查看本次模拟结果；重新加载页面会重新生成数据。「刷新」在演示模式中保留当前模拟快照，并清空任务选择。主题、桌面侧栏收起状态，以及任务列表的每页条数、行间距和辅助列偏好保存在浏览器本地存储；任务数据和选中记录不会随这些偏好持久化。监控配置草稿也可保存在本机，并按数据模式与项目 ID 隔离，具体行为见下文「监控面板」。

### 读取项目配置

默认入口使用「管理服务」，请求同源 `GET /api/healing/snapshot`。真实模式的含义是读取当前网关，不表示 Agent 已经在线。

| 内容           | 优先读取                      | 优先文件不存在时读取                  |
| -------------- | ----------------------------- | ------------------------------------- |
| 项目与执行策略 | `configs/healing-config.json` | `configs/healing-config.example.json` |
| 路由规则       | `configs/healing-rules.json`  | `configs/healing-rules.example.json`  |

需要自定义配置时可复制模板：

```bash
cp configs/healing-config.example.json configs/healing-config.json
cp configs/healing-rules.example.json configs/healing-rules.json
```

编辑文件后，在「连接设置」点击「刷新」。服务每次请求都会重新读取文件，配置与规则分别显示来源。实际文件存在但格式错误或无法读取时，服务返回明确错误；页面保留错误状态，不自动显示演示数据。当前没有 `.env` 加载或模板变量替换逻辑，`{{...}}` 占位符不会自动解析为凭据。

配置响应使用逐层字段白名单。模型 API key、GitHub 私钥、Webhook secret 等敏感字段不进入响应。完整规则导出、规则执行和配置写回不属于当前 API；允许输出的字段及错误结构见 [API 文档](console-api.md)。

## 2. 使用工作台

| 页面     | 可查看或操作的内容                                                                      |
| -------- | --------------------------------------------------------------------------------------- |
| 工作台   | 查看运行概览、待办审批与任务记录，进入对应处理页面                                      |
| 全部任务 | 搜索任务，组合筛选、排序、分页和跨页选择，确认后模拟批量取消或重试，导出任务摘要        |
| 审批中心 | 选择审批请求，查看节点图、候选 diff、验证证据、负责人、意见及跨轮次历史                 |
| 监控面板 | 配置 Grafana、Prometheus 数据源与命名空间，预览面板布局，打开外部仪表盘或导出配置与模板 |
| 操作记录 | 按日期查看任务操作、审批与规则变更，组合搜索和筛选，导出当前筛选记录                    |
| 执行引擎 | 查看 `fast` / `complex` 路由、配置模型与引擎类型；当前显示未接入                        |
| 路由规则 | 查看完整匹配条件、引擎与处理动作；满足演示能力条件时可切换规则开关                      |
| 安全策略 | 查看保护路径、单次文件上限、检查命令、回滚与熔断配置                                    |
| 连接设置 | 切换数据来源、刷新和检查连接状态；展开接入说明查看接口及配置来源                        |

任务详情从任务名称或操作记录中的关联任务打开，提供「执行过程」「代码变更」「验证证据」「日志」页签。

### 工作台：统计、任务与辅助信息

首页将「运行与排队」「待审批」「修复成功率」「平均修复耗时」合并在统一统计带中。最近任务主区提供「全部」「运行与排队」「待审批」三个视图，最多显示六条记录，可从任务直接进入详情或对应审批。辅助栏集中展示待审批请求、任务结果趋势和执行引擎配置入口；完整操作记录仍可从侧栏独立访问。

首页时间范围提供「今天」「近 7 天」「近 30 天」；全部任务使用独立时间范围，默认「全部时间」，与首页互不影响。筛选与趋势都按任务创建时间及 `Asia/Shanghai` 日历日期计算，包含当天，排除未来时间。成功率只计算 `completed / (completed + failed)`；运行、排队、取消和跳过的任务不进入分母。平均耗时仅取已完成或失败且有有效耗时的记录。没有可计算数据时显示 `—`。

结果趋势保留所选范围内的每日分组，展示这些任务当前已完成和失败的数量。「今天」显示单日日期，近 7 天与近 30 天保留起、中、末三个日期标签；鼠标悬停或键盘聚焦单日可查看具体数量。当前范围没有已完成或失败的任务时显示明确空态，不生成示例曲线。

### 全部任务：筛选、排序与显示

任务页把常用状态、搜索和工具栏放在列表上方，搜索旁集中放置「筛选」与「显示」，「导出」位于工具栏右侧。桌面常规任务行约 64px，紧凑模式约 56px；窄屏下的长标题允许自然换行并增高。每行用两层信息呈现任务名称和「ID · 问题类型」，高或紧急优先级显示一个小箭头；标题及元数据的悬停提示补充仓库、分支和完整优先级。名称和复选框是独立的点击目标。点击名称打开详情，行末菜单按任务情况提供详情、代码变更、审批流程、复制 ID 及可用的取消或重试入口。

| 控件       | 使用方式                                                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 状态快捷项 | 在「全部」「运行中」「待审批」「失败」「已完成」间切换；「队列中」「已取消」「已跳过」可在详细筛选中选择                                                   |
| 搜索       | 对任务名称、ID、仓库、分支及相关文件执行不区分大小写的字面量匹配；不执行正则表达式                                                                         |
| 筛选       | 展开面板后组合状态、执行引擎、任务类型、优先级、触发来源、分支和创建时间；不同条件取交集，分类选项来自当前快照中的实际任务                                 |
| 创建时间   | 位于筛选面板，可选「全部时间」「今天」「近 7 天」「近 30 天」「近 90 天」，使用北京时间的日历边界                                                          |
| 已应用条件 | 详细筛选显示为可移除标签；关键词留在搜索框，常用状态由选中项表示。可通过标签区「清除全部」或筛选面板「重置筛选」恢复默认；改变条件后回到第一页并清空原选择 |
| 排序       | 位于「显示」面板，可选「最新创建」「最早创建」「优先级从高到低」「耗时从长到短」；创建时间表头也可直接切换时间顺序                                         |
| 分页       | 默认每页 10 项，可选 20 或 50 项；页脚随列表滚动，显示当前范围、总数和页码，不覆盖任务行                                                                   |
| 显示       | 集中管理排序、舒适／紧凑行间距，以及执行引擎、耗时、创建时间三列的可见性；任务、状态和选择入口持续保留                                                     |

「触发来源」指手动发起、Webhook 或定时巡检，对应 `task.metadata.triggeredBy`。任务页中的「待审批」由 `reviewState: "pending"` 投影，和「队列中」互斥；它没有新增底层任务状态。状态项上的数字保留其他筛选条件，仅忽略当前选中的状态，因此可以直接比较同一搜索范围内的待办与结果数量。

排序、翻页、改变每页条数或显示方式会保留已选任务；搜索与筛选实际改变时会清空选择并提示。再次点击当前状态、提交未变化的详细筛选，或在条件已为默认值时重置筛选，会保留已选任务、当前页码和批量操作结果，同时按原有规则关闭浮层并恢复控件焦点。无匹配结果时可清除筛选；真实服务尚无任务时会显示空状态及连接设置入口。

### 跨页选择、批量处理与导出

表头复选框只选择或取消选择**当前页**。选中部分行时显示部分选中状态；已有选择后，批量栏会显示总选中数，并提供「选择全部 N 项筛选结果」以明确扩展到其他页面。翻页可以继续勾选，选择依据任务 ID 保存。「清空选择」、改变筛选、刷新数据、切换数据来源或完成批量操作都会清理选择；已经从快照移除的 ID 也会被剔除。

批量栏的取消和重试按钮显示当前符合条件的任务数量。打开确认框后，先检查「将处理」和「将跳过」两组任务及逐项原因，再确认操作。确认前会重新检查当前数据；状态或能力发生变化时，需要依据更新后的范围再次确认。操作结果会显示完成和跳过数量，并可展开逐项详情；重试结果同时提供原 ID、新 ID 和新任务入口。

| 批量操作 | 可执行任务                                                       | 结果与跳过规则                                                                                                     |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 取消任务 | 原始状态为 `pending` 或 `running`，包含等待审批的 `pending` 任务 | 变为 `cancelled`；保留已有证据、审批决定和取消记录，停止后续审批；其他状态或不存在的任务逐项跳过                   |
| 重试     | 原始状态为 `failed` 或 `cancelled`                               | 每项新建独立 ID 的 `pending` 任务，记录 `retryOf` 并递增重试次数；保留原任务和历史；其他状态或不存在的任务逐项跳过 |
| 导出选中 | 当前明确选中的任务                                               | 下载这些任务的 CSV 摘要，可包含跨页选择；不修改任务                                                                |

取消和重试同时要求演示模式以及对应 capability 为 `true`。没有符合条件的任务时按钮禁用，真实模式始终保持只读；不会因为选择了多项任务而放宽状态限制。批量操作只提供取消、重试和导出，审批仍需在审批中心逐关审阅。

列表工具栏中的「导出」下载**全部筛选结果**，范围包含其他页面；批量栏中的「导出选中」只下载已勾选项。文件名标记 `demo` 或 `live` 及 `filtered` 或 `selected`。CSV 使用 UTF-8 BOM、中文表头，字段固定为任务 ID、标题、类型、显示状态、优先级、执行引擎、触发来源、仓库、分支、创建时间、耗时（毫秒）。显示列偏好不会改变导出字段；没有可用耗时的单元格为空。

导出只投影上述摘要字段，不包含原始 payload、上下文、诊断日志、凭据或完整证据。逗号、引号和换行按 CSV 规则转义；可能被电子表格解释为公式的文本会加前置单引号处理，包括前面带空白或控制字符的情况。

### 操作记录与执行日志

「操作记录」回答谁在何时做了什么，按北京时间日期分组，展示服务提供的操作者、操作类型和原始说明；操作者缺失时明确标记未提供。v7 将动作和操作者放在同一标题层，说明与关联入口紧随其后；常规事件行约 84px，长失败说明自然增高。执行过程中的诊断输出保留在单个任务详情的「日志」页签，记录中的任务 ID 和「执行日志」入口可直接跳转。

可组合关键词、操作类型和时间范围筛选。关键词匹配操作者、操作说明、任务 ID 等公开字段；操作类型包括任务操作、审批操作、规则变更及其他操作，时间默认全部，可选今天或近 7／30／90 天。页面显示筛选后的数量，无记录或无匹配结果时提供相应空状态。

「导出记录」下载当前筛选结果的 JSON，包含模式、导出时间、数量与公开操作字段。导出不会携带整个快照、任务 payload、完整证据或额外嵌套数据；没有匹配记录时不生成空文件。

### 路由规则

规则列表以「当满足以下条件 → 交给引擎处理」呈现，可按规则名、ID、条件或动作搜索，并组合配置状态和引擎筛选。页面保留收到的每项匹配条件，例如 CI 规则同时展示「任务类型为 CI 失败」与「重试次数小于 3」。规则详情进一步列出引擎、处理动作、任务优先级、工作流，并可展开配置 JSON。

列表保留配置顺序，任务优先级属于处理配置；当前没有规则命中统计或规则排序执行器。只有页面和快照都处于 `demo` 模式，且 `capabilities.updateRules === true` 时，才允许更新内存中的规则开关并追加操作记录。管理服务模式保持只读，配置启用状态不代表引擎已经运行。

### 监控面板

监控面板包含「面板预览」和「接入配置」两个视图，为后续接入 Grafana 与 Prometheus 提供配置入口。管理服务从快照读取可选 `monitoring` 配置；旧配置未提供此字段时显示未配置状态，监控字段错误也不会阻断其他配置的读取。

在接入配置中填写 Grafana 基础地址、仪表盘 UID 与路径名称、Prometheus 数据源 UID、可选的显示名称，以及明确的命名空间列表。UID 用于绑定目标，显示名称仅用于阅读。高级配置提供组织 ID 和命名空间、数据源变量名。

「保存到本机」先校验字段，再按当前 `demo`／`live` 模式和项目 ID 保存独立草稿；浏览器存储不可用时会说明仅本次会话有效。「恢复来源配置」清除当前草稿并重新使用示例或服务端配置。本机保存和导出都不会写回服务器；要让管理服务读取配置，需将导出的 `monitoring` 块合并到 `configs/healing-config.json` 后刷新。

面板预览将命名空间、时间范围、数据源名称与 UID、外部仪表盘入口集中在紧凑工具栏中，可在已配置命名空间中选择单项或全部已配置项。「可抓取目标」和「抓取异常」保持 `—`；已配置命名空间数来自配置，并单独说明当前查看范围。空态区根据示例地址、无配置、无效配置或有效但未验证的配置显示对应说明，减少重复提示。「打开 Grafana」在新标签页访问目标仪表盘，示例占位地址需要替换后才能打开。「导出配置」生成配置片段，「导出仪表盘模板」生成可导入的 Grafana JSON；模板使用具有 `namespace` 标签的 Prometheus `up` 抓取状态查询。

当前页面提供布局预览，不执行远端连通性检查、不加载 iframe，也不显示真实指标；配置校验通过仍标记连接未验证。命名空间选择仅影响仪表盘展示范围，不改变 Agent 的实际 watch／监听范围。字段约束、变量绑定、模板含义和服务端接入步骤见 [Grafana 与 Prometheus 监控对接](monitoring-integration.md)。

### 侧栏与连接状态

侧栏使用完整页面名称：工作区依次为「工作台」「全部任务」「审批中心」「监控面板」「操作记录」，配置区为「执行引擎」「路由规则」「安全策略」，底部为「连接设置」及主题、收起按钮。当前页面、悬停和键盘焦点各有反馈；审批旁的数字来自当前完整快照中的待审批记录。

桌面底部的收起按钮切换图标导航并记住偏好；收起后保留页面名称提示。主题按钮用于切换浅色或深色外观。顶部用一个「演示」「只读」「连接异常」或「连接中」标识呈现当前连接状态，点击进入连接设置。任务页已提供搜索框，其他页面可通过顶部「搜索任务…」入口或 `⌘ K` / `Ctrl K` 进入任务搜索；窄屏将该入口收为搜索图标。页面导航完成后，焦点移到主要内容区域，便于继续使用键盘浏览；打开任务搜索时再聚焦搜索输入框。

窄屏使用导航抽屉，可通过关闭按钮、背景遮罩或 Escape 退出；打开时限制背景交互并把键盘焦点留在抽屉内。任务页优先保留任务和状态，辅助列按空间调整。v4 的模块职责、选择范围和验收记录见 [任务工作区设计说明](design/task-workspace-v4.md)。

### 连接设置

从侧栏「连接设置」或顶部连接标识进入。一张「数据来源」卡片集中提供两项来源：选择「交互演示」查看会话内模拟任务，选择「管理服务」读取同源只读配置。下方显示项目、分支、连接状态和最近读取时间，并分别说明演示操作／配置读取是否可用、真实执行是否接入。

连接可用时，卡片右上方提供「刷新」；连接失败时，错误原因和「重新连接」按钮就地显示在来源选项下方。卡片底部的「接入与接口信息」默认收起，展开后可查看本地启动命令、默认地址、快照接口、实际或示例配置文件来源，以及真实写接口的 `501` 边界。

### 演示操作的状态变化

| 操作         | 适用对象                                | 结果                                                                                          |
| ------------ | --------------------------------------- | --------------------------------------------------------------------------------------------- |
| 发起巡检     | 演示模式，填写标题、类型、优先级和分支  | 新增 `pending` 手动任务，不会启动实际执行                                                     |
| 取消任务     | `pending` 或 `running`                  | 改为 `cancelled`；审批任务同时停止流程，保留已经完成的检查证据和决定记录                      |
| 重新尝试     | `failed` 或 `cancelled`                 | 保留原记录，新建 `pending` 任务，并增加 `context.retryCount`                                  |
| 通过代码审阅 | 当前节点为 `code-review`                | 当前关卡完成，解锁 `execution-auth`；`reviewState` 仍为 `pending`                             |
| 确认执行授权 | 当前节点为 `execution-auth`             | 两个人工关卡全部完成，`reviewState` 为 `approved`；任务仍为 `pending`，执行节点显示等待执行器 |
| 拒绝方案     | 当前可处理的人工关卡，填写 1–500 字原因 | `reviewState` 改为 `rejected`，任务为 `cancelled`，后续节点保持阻塞并记录原因                 |
| 重新发起审批 | 已拒绝的请求，填写 1–500 字说明         | 开始新一轮两级审批；保留历史并沿用原候选方案及原检查证据                                      |
| 切换路由规则 | 已存在的演示规则                        | 更新内存中的 `enabled`，不写回配置文件                                                        |

每次模拟操作会追加操作记录。审批使用单独的 `reviewState` 字段，原有 `TaskStatus` 的六种状态保持不变。

### 两级审批流程

从首页「查看审批流」、任务详情「打开审批流」或侧栏「审批中心」进入审批中心。左侧可以在待处理和全部记录之间切换；右侧提供「审批流程」「候选变更」「审批记录」三个页签。流程图可以点击节点，查看该节点的状态、负责人、时间、意见和相关证据；画布支持缩放、适应与横向滚动。

| 节点                       | 含义及推进条件                                                 |
| -------------------------- | -------------------------------------------------------------- |
| `plan`：诊断与方案         | 展示 Agent 生成候选方案的显式证据                              |
| `quality`：质量验证        | 展示类型与回归检查证据，与安全检查并行呈现                     |
| `safety`：安全检查         | 展示变更范围与保护路径检查证据                                 |
| `code-review`：代码审阅    | 自动检查证据完整后，由演示负责人 Qd99 审阅候选 diff 与验证结果 |
| `execution-auth`：执行授权 | 代码审阅通过后才解锁，由演示负责人再次确认执行授权             |
| `execute`：执行与归档      | 两关通过后只进入等待执行器状态，当前不会执行修复或提交变更     |

通过审批时意见可选；拒绝必须填写原因。每次决定绑定当前 `nodeId` 和 `round`，避免旧节点或上一轮表单推进新的关卡。已经处理或尚未解锁的节点不能再次批准。所有负责人均为演示信息，不代表登录身份、真实岗位权限或多人协作认证。

拒绝后，可以查看原决定并重新提交说明。重新发起只重开审批，不修改候选 diff，也不重新执行自动检查；原证据和旧轮次记录持续保留。取消任务同样保留流程、检查证据与决定，但停止后续步骤，不能继续审批。没有显式节点证据时，界面显示暂无证据或尚未接入，不从“已配置”推断检查已经通过。

### 键盘与窄屏

`⌘ K` 或 `Ctrl K` 打开任务搜索。详情和创建表单使用原生对话框，支持 Escape 关闭与关闭后的焦点恢复；页签支持左右方向键、Home 和 End。页面有跳转到主要内容的入口及可见焦点样式，常规页面导航也会将焦点移到主要内容。任务筛选重绘后恢复对应控件的焦点，重复应用未变化的条件不会清空选择。

窄屏通过菜单按钮打开侧栏，任务详情与审批保留触控入口；流程画布根据可用宽度调整展示，并允许横向滚动，完整节点信息仍可访问。样式包含浅色、深色及 `prefers-reduced-motion` 适配。已有版本的交互验收范围见 [v3 验收记录](design/validation.md) 和 [v4 任务工作区记录](design/task-workspace-v4.md)。

## 3. 设计沿革与 v7 共用组件

### v7 布局与共用组件

各模块统一使用 `apps/console/public/ui.js` 的按钮、搜索、下拉框、状态、页签、空状态与 `uiMetric` 图标数据卡，以及 `ui.css` 的主题和交互样式。v7 用浅灰画布和工作表面区分层级，收紧导航、标题与模块间距；静态卡片和统计块保持稳定，实际控件保留边框、底色与轻微按压反馈。选中的导航项通过浅靛蓝背景和图标颜色标识，浅色与深色主题共用同一套语义变量。

`interaction.js` 为重绘后的控件保留短暂点击反馈；实际结果仍由业务状态或提示确认，手动刷新明确报告成功／失败。模块 CSS 只补充自身布局，继续使用浏览器 ES modules 与原生对话框，并尊重减少动画偏好。v7 的变更、筛选修复与验证范围见 [本轮设计记录](design/console-v7.md)。

### 保留的 v3／v4 设计记录

v3 曾采用蓝灰色的实感玻璃工作台，借助高光、阴影和局部渐变区分运行概览、流程画布与审批请求。以下保留历史设计决策；当前 v7 外观由共用组件提供，两级审批状态和证据结构继续沿用。

| v3 设计决策        | 历史实现                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| 蓝灰实感玻璃       | 蓝灰画布、较实的浅色面板、细边缘高光和柔和阴影；主按钮及选中态使用蓝色强调                          |
| 语义图标体系       | 导航、任务类型、Agent、质量验证、安全检查和审批节点使用不同 Lucide 图标；节点图标配有小范围渐变底座 |
| 流程作为视觉焦点   | 首页展示审批进展，审批中心使用可点选节点与连线，质量和安全检查并行呈现                              |
| 状态明确           | 已完成、当前待审批、等待前序、已拒绝、等待执行器和已取消均有文字与图标，颜色提供辅助区分            |

| 同源静态服务、配置读取、来源标记及敏感字段白名单       | 已实现                                                  |
| 操作记录筛选与 JSON 导出、完整规则条件展示             | 基于当前快照；规则开关仅在具备能力的演示中更新          |
| 监控配置投影、模式与项目隔离的本机草稿                 | 已实现；配置导出后需另行合并到服务端配置                |
| Grafana 外部链接、监控配置与仪表盘 JSON 导出           | 已实现；面板预览无实时指标，不探测远端连接或加载 iframe |
| 复用 `Task`、`TaskStatusInfo`、`Result` 的 JSON 契约   | 已实现；日期转为 ISO 字符串，UI 扩展字段独立定义        |
| EventHub、实际队列、事件路由执行                       | 尚未接入                                                |
| Direct AI、ZCode 或其他具体 `WorkflowEngine`           | 尚未实现或接入                                          |
| Webhook 接收、Cron 调度、GitHub App 仓库操作           | 尚未接入                                                |
| 真实触发、取消、重试、审批、规则写回                   | 尚未接入；已列出的任务写接口返回 `501`                  |
| 安全检查、CI 验证、自动回滚与熔断执行                  | 当前只展示策略配置                                      |
| 登录、RBAC、任务及审计持久化                           | 尚未实现                                                |
| 实时推送、自动轮询任务状态                             | 尚未实现，连接设置可手动刷新                            |

因此，真实模式下任务和操作记录列表为空，写操作 capability 均为 `false`。引擎的 `configured` 表示找到配置；`implemented: false` 和 `status: unavailable` 如实表示没有连接执行器。监控的 `ready` 仅表示字段有效，`connectivity` 始终为 `unverified`。项目名称和演示审批负责人属于展示信息，不代表登录认证。

接入实际系统时，应先实现 `WorkflowEngine` 的执行、健康检查、取消与状态查询，并把任务结果投影到 `ConsoleTask` 契约；再接入队列、审计存储及有权限校验的写接口，按真实可用能力开放 capability。前端目前只对演示操作执行本地更新，真实写操作还需要对应的客户端请求逻辑。协议、路由及安全字段边界见 [API 文档](console-api.md)。

## 5. 开发、构建与验收

日常测试与构建命令：

```bash
npm install
npm test
npm run typecheck
npm run build
```

`npm test` 使用 Node 内置测试运行器。`typecheck` 检查 `packages/framework/src/**/*.ts` 的严格类型契约，当前不对浏览器 JavaScript 进行 TypeScript 检查。`build` 先运行该类型检查，再复制静态管理台到 `dist/`。

| 命令                                  | 产物或行为                                   |
| ------------------------------------- | -------------------------------------------- |
| `npm run build:console`               | 将前端复制到 `dist/`，默认读取同源 API       |
| `npm run build:demo`                  | 将前端复制到 `dist/`，并明确设置默认演示模式 |
| `npm run test:watch`                  | 监听测试文件变化并重新运行                   |
| `node apps/healing-hub/src/index.mjs` | 直接启动本地工作台与配置 API                 |

构建命令会重新生成 `dist/`。静态构建只包含前端资源，不包含 Node 网关或执行器；普通静态托管适合演示模式。真实模式需要在同一来源提供 `/api/healing/snapshot`。请通过 HTTP 服务打开模块页面，不直接双击 `index.html`。
