# Web 工作台使用与设计说明

`heal` v11 已将工作台接入同源持久管理 API。任务创建、取消、重试、两级审批、规则开关、监控配置和操作记录均由服务端校验并保存；前端收到成功响应后才更新结果。服务提供 Agent 领取、诊断提案、执行回传和取消确认协议，未连接执行器时如实显示排队状态，不生成虚构成功记录。现有任务筛选、报表、审批流程图和连接列表继续保留。协议见 [管理 API](console-api.md) 与 [Agent 接入](agent-worker-api.md)，本轮验证范围见 [v11 接口接入记录](design/console-v11-integration.md)。

## 1. 本地运行

要求 Node.js 18 或更新版本。在仓库根目录运行：

```bash
npm run dev
```

默认访问 [http://127.0.0.1:8787/](http://127.0.0.1:8787/)。`npm start` 使用同一个入口。网关与前端静态资源由同一服务提供；当前启动过程使用 Node 内置模块，运行工作台本身不依赖 Redis、MySQL、GitHub App 或第三方模型凭据。

可通过环境变量调整端口：

```bash
PORT=8790 npm run dev
```

默认监听 `127.0.0.1`，`HOST` 可显式覆盖监听地址。无管理令牌时仅接受真实回环连接和回环 Host，本机写操作仍校验 CSRF。非回环监听必须设置 `CONSOLE_API_TOKEN`；远程部署使用 HTTPS 反向代理，让 UI 与 API 保持同源，并设置 `CONSOLE_SECURE_COOKIE=true`。

在登录表单输入管理令牌后，服务建立 8 小时 HttpOnly 会话；令牌不写入浏览器本地存储，服务重启后需要重新登录。当前是单管理身份控制台，不包含多用户 RBAC。审计名称可通过 `CONSOLE_OPERATOR_NAME` 设置。Agent 使用独立的 `HEALING_WORKER_TOKEN`，不能用管理令牌代替，也不能代替管理者审批。环境变量、反向代理和会话细节见 [启动与认证](console-api.md#启动与部署)。

状态默认保存在 `.healing/console-state.json`，可通过 `HEALING_DATA_DIR` 指定持久目录；目录必须位于静态资源目录之外。页面刷新和正常重启保留任务、审批、规则覆盖、监控配置与审计。该存储只支持单个服务实例，备份、容量和异常锁处理见 [状态持久化与运维](console-api.md#状态持久化与运维)。

### 默认入口与数据状态

默认入口请求同源 `GET /api/healing/snapshot`，读取实际持久状态。全新的数据目录可以没有任务或操作记录；创建任务后，记录会保留并出现在后续快照中。读取管理服务成功不表示 Agent 已在线，创建成功也只表示任务已保存并进入队列。

真实模式在适合刷新时每 15 秒尝试读取最新快照。页面隐藏、正在提交、输入框聚焦、对话框打开，或有未保存监控配置和审批意见时暂停自动刷新。读取失败会保留已显示数据和编辑内容，并提示连接问题；不会据此假定写入成功，也不会自动重发写请求。

没有管理 API 的静态托管、连接超时或无效响应会保留未连接／读取失败状态。页面不会自动切换为测试数据，也不会把本地空状态当成一次成功读取。可在「连接设置」查看原因并重新连接。需要有数据的交互测试时，由开发者显式启用第 5 节说明的测试样本。

### 读取项目配置

管理服务每次请求分别读取项目配置与路由规则：

| 内容           | 优先读取                      | 优先文件不存在时读取                  |
| -------------- | ----------------------------- | ------------------------------------- |
| 项目与执行策略 | `configs/healing-config.json` | `configs/healing-config.example.json` |
| 路由规则       | `configs/healing-rules.json`  | `configs/healing-rules.example.json`  |

需要自定义配置时可复制模板：

```bash
cp configs/healing-config.example.json configs/healing-config.json
cp configs/healing-rules.example.json configs/healing-rules.json
```

编辑文件后，刷新「连接设置」中的管理服务连接。服务每次请求都会重新读取文件，配置与规则分别显示来源；规则开关和监控配置的已保存覆盖会叠加到基础配置上。`rulesOverridden` 与 `monitoringSource` 区分这些持久覆盖，原文件中的凭据不会被页面保存操作改写。实际文件存在但格式错误或无法读取时，服务返回明确错误，不自动退回示例。当前没有 `.env` 加载或模板变量替换逻辑，`{{...}}` 占位符不会自动解析为凭据。

配置响应使用逐层字段白名单。模型 API key、GitHub 私钥、Webhook secret 等敏感字段不进入响应。规则开关由 API 保存并参与新建／重试任务的路由；当前不提供完整规则编辑或原始配置文件写回。允许输出的字段及错误结构见 [API 文档](console-api.md)。

## 2. 使用工作台

| 页面     | 可查看或操作的内容                                                          |
| -------- | --------------------------------------------------------------------------- |
| 工作台   | 查看任务指标、趋势、状态构成、问题类型与引擎表现，从分类进入任务列表        |
| 全部任务 | 创建、筛选、排序、分页、跨页选择、取消、重试、批量操作与任务摘要导出        |
| 审批中心 | 查看候选方案、实际证据、两级审批节点、意见和持久历史，批准、拒绝或重新提交  |
| 监控面板 | 保存服务端 Grafana／Prometheus 配置，检查连接身份，打开外部仪表盘或导出模板 |
| 操作记录 | 查看持久审计表格与详情，组合筛选，每页 15 条，导出全部匹配记录              |
| 执行引擎 | 查看配置与最近 Worker 通信；没有活跃执行器时显示不可用                      |
| 路由规则 | 查看完整匹配条件和处理动作，通过 API 保存规则开关                           |
| 安全策略 | 查看任务采用的保护路径、文件上限和检查要求；回滚／熔断仍是配置规划          |
| 连接设置 | 登录及刷新管理服务，查看 Grafana／Prometheus 配置和检查结果                 |

任务详情从任务名称或操作记录中的关联任务打开，提供「执行过程」「代码变更」「验证证据」「日志」页签。

### 工作台：报表与最近任务

真实模式首页顶部展示「任务总量」「任务成功率」「平均任务耗时」「待审批」四项指标，图标与颜色用于区分含义；显式演示模式保留原示例标签。主区展示任务趋势和状态构成，下方安排问题类型排行、引擎表现及最近任务。完整审批流程仍在审批中心，操作记录仍可从侧栏访问。

| 报表     | 内容与交互                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------- |
| 任务趋势 | 按创建日期补齐每日分组，堆叠显示已完成、失败和其他状态；悬停或键盘聚焦日柱查看当日任务数。         |
| 任务状态 | 环形图中心显示当前范围的总任务数，图例列出互斥状态数量和占比；可定位的状态可点击进入任务列表。     |
| 问题类型 | 按任务量排列，先展示五类，其余可展开。横条长度相对最多的分类，右侧百分比以当前范围全部任务为分母。 |
| 引擎表现 | 按分配给各引擎的任务展示数量、任务成功率、平均有效耗时与完成／失败／其他构成；点击可查看对应任务。 |

最近任务提供「全部」「运行/排队」「待审批」三个视图，最多显示四条记录。点击任务进入详情或对应审批；「查看全部」打开当前首页时间范围内的全部任务。待审批指标统计当前范围，「去审批」进入完整审批中心。

首页时间范围提供「今天」「近 7 天」「近 30 天」。所有首页指标和报表使用同一份过滤结果，按任务创建时间及 `Asia/Shanghai` 日历日期计算，包含当天，排除未来和无效时间。趋势中的已完成／失败表示**这些日期创建的任务当前结果**，不表示在对应日期实际完成的数量；「其他」包含未完成以及取消、跳过或未知等状态。状态构成中待审批优先，与排队互斥，不重复计数。

任务成功率计算 `completed / (completed + failed)`；运行、排队、取消和跳过不进入分母。已完成任务既可能是提交代码／创建 PR，也可能是创建 Issue 或完成 CI 重试，因此该指标不是代码修复成功率、检查通过率或应用健康率。租约过期会形成失败记录，表示执行结果未知，不能据此认定远端操作没有发生。状态图中「已完成」的占比以全部任务为分母，和任务成功率含义不同。

平均任务耗时仅纳入已完成或失败且具有有效耗时的记录，优先使用 `result.timings.durationMs`，缺失时使用有效的开始／结束时间差；缺失或非法耗时不当作零。当前服务从首次领取诊断任务到最终结果记录计时，可能包含人工审批及后续执行排队等待，不等于模型计算时间或纯命令运行时间，也不包含首次领取前的排队时间。无可计算数据时显示 `—`，无任务时显示空态。引擎报表按分配任务聚合，任务类型、数量与难度可能不同，不能据此作公平性能排名或判断引擎在线状态。

### 从报表查看任务

点击状态图例、可定位的问题类型或引擎，会进入全部任务，应用**当前首页时间范围＋这一项分类条件**。旧关键词、其他筛选、跨页选择、批量结果和浮层会清理，页码回到第一页，排序恢复为最新创建。页面显示密度、每页条数和辅助列偏好保留。未知聚合项无法准确对应列表筛选时只展示，不提供下钻。

首页和任务页各自维护时间条件，任务页首次默认「全部时间」；通过报表进入时会主动带入首页范围。之后在任务页继续调整筛选不会改变首页时间范围。报表聚合与下钻仍只读取当前快照，不发起 Agent 执行或修改后端配置。

### 全部任务：筛选、排序与显示

任务页把常用状态、搜索和工具栏放在列表上方，搜索旁集中放置「筛选」与「显示」，「导出」位于工具栏右侧。桌面常规任务行约 64px，紧凑模式约 56px；窄屏下的长标题允许自然换行并增高。每行用两层信息呈现任务名称和「ID · 问题类型」，高或紧急优先级显示一个小箭头；标题及元数据的悬停提示补充仓库、分支和完整优先级。名称和复选框是独立的点击目标。点击名称打开详情，行末菜单按任务情况提供详情、代码变更、审批流程、复制 ID 及可用的取消或重试入口。

| 控件       | 使用方式                                                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 状态快捷项 | 在「全部」「运行中」「待审批」「失败」「已完成」间切换；「队列中」「已取消」「已跳过」可在详细筛选中选择                                                   |
| 搜索       | 对任务名称、ID、仓库、分支及相关文件执行不区分大小写的字面量匹配；不执行正则表达式                                                                         |
| 筛选       | 展开面板后组合状态、执行引擎、任务类型、优先级、触发来源、分支和创建时间；不同条件取交集，分类选项来自当前快照中的实际任务                                 |
| 创建时间   | 位于筛选面板，可选「全部时间」「今天」「近 7 天」「近 30 天」「近 90 天」，使用北京时间的日历边界                                                          |
| 已应用条件 | 详细筛选显示为可移除标签；关键词留在搜索框，常用状态由选中项表示。可通过标签区「清除全部」或筛选面板「重置筛选」恢复默认；改变条件后回到第一页并清空原选择 |
| 排序       | 位于「显示」面板，可选「最新创建」「最早创建」「优先级从高到低」「耗时从长到短」；创建时间表头也可直接切换时间顺序                                         |
| 分页       | 默认每页 10 项，可选 20 或 50 项；页脚随列表滚动，显示当前范围、总数和页码，不覆盖任务行                                                                   |
| 显示       | 集中管理排序、舒适／紧凑行间距，以及执行引擎、耗时、创建时间三列的可见性；任务、状态和选择入口持续保留                                                     |

「触发来源」按契约区分手动发起、Webhook 或定时巡检，对应 `task.metadata.triggeredBy`；当前实际入口是手动 API，Webhook 接收和定时调度组件尚未实现。任务页中的「待审批」由 `reviewState: "pending"` 投影，和「队列中」互斥；它没有新增底层任务状态。状态项上的数字保留其他筛选条件，仅忽略当前选中的状态，因此可以直接比较同一搜索范围内的待办与结果数量。

主题、桌面侧栏收起状态，以及任务列表的每页条数、行间距和辅助列偏好保存在浏览器本地存储。真实任务数据由服务端持久化；跨页选择只属于当前页面操作，不随显示偏好保存。

排序、翻页、改变每页条数或显示方式会保留已选任务；搜索与筛选实际改变时会清空选择并提示。再次点击当前状态、提交未变化的详细筛选，或在条件已为默认值时重置筛选，会保留已选任务、当前页码和批量操作结果，同时按原有规则关闭浮层并恢复控件焦点。无匹配结果时可清除筛选；真实服务尚无任务时会显示空状态及连接设置入口。

### 跨页选择、批量处理与导出

表头复选框只选择或取消选择**当前页**。选中部分行时显示部分选中状态；已有选择后，批量栏会显示总选中数，并提供「选择全部 N 项筛选结果」以明确扩展到其他页面。翻页可以继续勾选，选择依据任务 ID 保存。「清空选择」、改变筛选或完成批量操作会清理选择；刷新后会按最新数据重新核对所选 ID，已经从快照移除的 ID 会被剔除。

批量栏的取消和重试按钮显示当前符合条件的任务数量。打开确认框后，先检查「将处理」和「将跳过」两组任务及逐项原因，再确认操作。确认前会重新检查当前数据；状态或能力发生变化时，需要依据更新后的范围再次确认。操作结果会显示完成和跳过数量，并可展开逐项详情；重试结果同时提供原 ID、新 ID 和新任务入口。

| 批量操作 | 可执行任务                                                       | 结果与跳过规则                                                                                                             |
| -------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 取消任务 | 原始状态为 `pending` 或 `running`，包含等待审批的 `pending` 任务 | 等待中任务变为 `cancelled`；运行中记录取消请求，等待 Worker 确认；保留证据和历史，其他状态、不存在或版本过期的任务逐项跳过 |
| 重试     | 原始状态为 `failed` 或 `cancelled`                               | 每项新建独立 ID 的 `pending` 任务，记录 `retryOf` 并递增重试次数；保留原任务和历史；其他状态或不存在的任务逐项跳过         |
| 导出选中 | 当前明确选中的任务                                               | 下载这些任务的 CSV 摘要，可包含跨页选择；不修改任务                                                                        |

真实模式通过管理 API 执行取消和重试，要求已认证且对应 capability 开启。请求携带各任务版本；合法但状态变化或版本过期的项会跳过并说明原因，批次最多 100 个唯一任务。没有符合条件的任务时按钮禁用；多选不会放宽任务状态限制。批量操作仅提供取消、重试和导出，审批仍需逐关审阅。显式演示模式保留对应的浏览器内存模拟，不写入真实队列。

列表工具栏中的「导出」下载**全部筛选结果**，范围包含其他页面；批量栏中的「导出选中」只下载已勾选项。文件名标记 `demo` 或 `live` 及 `filtered` 或 `selected`。CSV 使用 UTF-8 BOM、中文表头，字段固定为任务 ID、标题、类型、显示状态、优先级、执行引擎、触发来源、仓库、分支、创建时间、耗时（毫秒）。显示列偏好不会改变导出字段；没有可用耗时的单元格为空。

导出只投影上述摘要字段，不包含原始 payload、上下文、诊断日志、凭据或完整证据。逗号、引号和换行按 CSV 规则转义；可能被电子表格解释为公式的文本会加前置单引号处理，包括前面带空白或控制字符的情况。

### 操作记录与执行日志

「操作记录」回答谁在何时做了什么。紧凑表格集中展示时间、操作、操作者、关联对象与级别；较长说明和记录详情按需展开。页面使用北京时间，操作类型、操作者及说明均来自记录本身，操作者缺失时明确标记未提供。执行过程中的诊断输出保留在单个任务详情的「日志」页签；关联任务可用时，记录详情提供任务与执行日志入口。

关键词、操作类型、时间范围和级别筛选取交集。关键词匹配操作者、操作说明、任务 ID 等公开字段；操作类型包括任务操作、审批操作、规则变更及其他操作，时间默认全部，可选今天或近 7／30／90 天，级别可按记录中的信息、成功、警告或错误筛选。列表每页显示 15 条，页脚展示当前范围和总数；改变筛选后回到第一页。

记录由服务端真实操作产生并与状态变更一并持久化，包括任务创建、领取、提案、审批、取消／重试、规则和监控保存。操作者来自管理会话或 Worker 认证上下文，不能由表单伪造。普通读取不会制造成功事件；读取时若发现真实租约过期，会记录对应失败。未读取管理服务时显示连接空态，成功读取后的空列表与筛选无匹配分别给出相应说明。「导出记录」下载**全部匹配记录**的 JSON，包含其他页面上的结果，不限于当前 15 条。文件包含模式、导出时间、数量与公开操作字段，不携带整个快照、任务 payload、完整证据或额外嵌套数据；没有匹配记录时不生成空文件。

### 路由规则

规则列表以「当满足以下条件 → 交给引擎处理」呈现，可按规则名、ID、条件或动作搜索，并组合配置状态和引擎筛选。页面保留收到的每项匹配条件，例如 CI 规则同时展示「任务类型为 CI 失败」与「重试次数小于 3」。规则详情进一步列出引擎、处理动作、任务优先级、工作流，并可展开配置 JSON。

列表保留配置顺序。真实创建／重试按顺序选择首个启用且匹配的规则，包括重试次数的各项比较；没有匹配规则时返回明确错误，不自动改用其他引擎。任务优先级属于任务处理配置，不改变这里的匹配顺序；当前没有规则命中统计。

真实模式的开关通过 `PATCH /api/healing/rules/:id` 显式保存 `enabled`，校验全局快照版本并追加操作记录，刷新和重启后继续生效。已创建任务保留当时选定的路由和安全策略；新任务和重试使用最新有效规则。演示模式只修改演示内存。规则启用不表示对应执行器已经在线。

### 监控面板

监控面板包含「面板预览」和「接入配置」。管理服务读取可选 `monitoring` 基础配置并叠加已保存覆盖；没有配置时显示未配置状态，监控字段错误不会阻断其他合法配置的读取。

填写 Grafana 基础地址、仪表盘 UID 与路径名称、Prometheus 数据源 UID、可选显示名称，以及明确的命名空间列表。UID 用于定位数据源，名称不能替代 UID；填写名称后，连接检查还会核对返回名称。高级配置提供组织 ID 和变量名。

真实模式点击「保存配置」，前端发送 `PUT /api/healing/monitoring`，服务校验全局版本、字段与权限后持久保存。成功响应到达前不会显示已保存；冲突或网络错误保留草稿并说明原因。「恢复来源配置」放弃当前未保存编辑，恢复最新服务端配置，不会删除服务端已保存覆盖。只有显式演示模式使用「保存到本机」；其草稿按模式和项目隔离，浏览器存储失败时仅当前会话有效。

保存成功与连接检查是两步操作。有未保存修改时先保存，再点击「检查连接」。服务仅检查已保存配置，响应 `{ check, monitoring, revision }` 包含实际检查的规范化配置及其快照版本。界面将结果绑定到这份配置；期间若配置已改变，不会把旧目标的成功结果显示为新目标已连接。`ready`／`connectivity: unverified` 仍描述配置状态，单独的检查结果描述某一时刻的 Grafana 健康与数据源身份。

面板预览将命名空间、时间范围、数据源名称与 UID、外部仪表盘入口放在紧凑工具栏中。可选单项或全部已配置命名空间；「可抓取目标」和「抓取异常」继续显示 `—`，命名空间数量仅来自配置。连接检查不查询指标，也不证明命名空间存在、Pod 健康或 Agent 正在监听。

「打开 Grafana」在新标签页访问目标仪表盘；示例地址须替换后使用。「导出配置」下载已保存的安全配置片段，「导出仪表盘模板」生成 Grafana JSON，使用具有 `namespace` 标签的 Prometheus `up` 查询。页面不加载 iframe。Agent 领取上下文可获得已保存监控配置，实际监听范围仍由 Agent 实现；页面范围选择仅改变外部仪表盘展示。允许来源、凭据、变量绑定和模板含义见 [监控对接文档](monitoring-integration.md)。

### 侧栏与连接状态

侧栏使用完整页面名称：工作区依次为「工作台」「全部任务」「审批中心」「监控面板」「操作记录」，配置区为「执行引擎」「路由规则」「安全策略」，底部为「连接设置」及主题、收起按钮。当前页面、悬停和键盘焦点各有反馈；审批旁的数字来自当前完整快照中的待审批记录。

桌面底部的收起按钮切换图标导航并记住偏好；收起后保留页面名称提示。主题按钮用于切换浅色或深色外观。顶部仅保留项目与当前页面的路径信息及窄屏菜单，不再展示全局任务搜索或演示／只读模式徽标。搜索任务时进入「全部任务」使用页面内搜索框；连接状态集中在「连接设置」。页面导航完成后，焦点移到主要内容区域，便于继续使用键盘浏览。

窄屏使用导航抽屉，可通过关闭按钮、背景遮罩或 Escape 退出；打开时限制背景交互并把键盘焦点留在抽屉内。任务页优先保留任务和状态，辅助列按空间调整。v4 的模块职责、选择范围和验收记录见 [任务工作区设计说明](design/task-workspace-v4.md)。

### 连接设置

从侧栏「连接设置」进入。页面以一份连接列表呈现「管理服务」「Grafana」「Prometheus」，每项先展示名称、状态和主要操作，详细信息默认收起。页面不再提供演示／管理服务来源切换。

管理服务项用于登录、刷新或重新连接同源 API。展开后可查看项目、分支、最近成功读取时间、快照接口及实际或示例配置文件来源；未成功读取时保持未连接或待认证状态，不补造项目或读取时间。会话失效后重新登录，不能继续把旧快照当成已授权的写操作上下文。

Grafana 和 Prometheus 项分别说明仪表盘与数据源配置，并提供监控配置和连接检查入口。真实模式以服务端配置为准，检查结果只关联其实际检查的配置；演示模式的本机草稿不会替代真实配置。地址、仪表盘 UID、数据源 UID 和命名空间在详情中查看，完整编辑仍在监控面板的「接入配置」。连接检查不代表已取得指标或验证集群监听。

### 真实任务操作与确认

| 操作           | 适用对象与结果                                                                      |
| -------------- | ----------------------------------------------------------------------------------- |
| 创建任务       | 填写标题、类型、优先级及可选描述／分支；服务端匹配路由并创建持久 `pending` 任务     |
| 取消任务       | 等待中直接取消；运行中先记录 `cancelRequested`，执行器确认后才变为 `cancelled`      |
| 重试           | 仅失败或取消任务；重新匹配当前规则，创建独立 ID，并保留原任务、`retryOf` 和重试次数 |
| 通过第一关     | 当前为 `code-review`；通过后只解锁 `execution-auth`，任务仍待审批                   |
| 通过第二关     | 当前为 `execution-auth`；通过后进入待领取执行阶段，不代表已经完成操作               |
| 拒绝／重新提交 | 拒绝阻止执行；重新提交保留同一候选及证据、递增轮次并重开两级审批                    |
| 保存规则／监控 | 持久保存公开覆盖并记录审计；不改写原配置文件中的秘密                                |

表单提交期间显示等待状态并阻止重复操作；只有服务端成功响应才确认结果。任务动作和审批使用任务版本，规则和监控保存使用快照版本，冲突返回 409 并提示重新核对。创建、任务动作及批量请求支持 `requestId`，网络结果不明确时保留同一请求标识，避免重复创建；客户端不自动重发写请求。

任务由已认证 Worker 领取后进入 `running`。提案释放诊断租约并等待审批；两关通过后，Worker 领取执行租约并回传实际结果。租约过期会记失败并保留“外部结果未知”的说明，不自动重跑。具体请求与证据约束见 [Agent 接入协议](agent-worker-api.md)。

显式开发测试继续支持对应的内存模拟操作；模拟通过审批只进入等待状态，不会领取真实 Worker、提交仓库或写入服务端。两种模式都使用独立的 `reviewState` 表示审批，底层 `TaskStatus` 六种状态不变。

### 两级审批流程

从首页「查看审批流」、任务详情「打开审批流」或侧栏「审批中心」进入审批中心。左侧可以在待处理和全部记录之间切换；右侧提供「审批流程」「候选变更」「审批记录」三个页签。流程图可以点击节点，查看该节点的状态、负责人、时间、意见和相关证据；画布支持缩放、适应与横向滚动。

| 节点                          | 含义及推进条件                                                               |
| ----------------------------- | ---------------------------------------------------------------------------- |
| `plan`：诊断与方案            | 展示 Worker 的实际候选摘要与证据                                             |
| `quality`：质量验证           | 代码方案要求必需检查通过；操作方案记录诊断结果，允许失败，不宣称代码检查通过 |
| `safety`：安全检查            | 服务端校验代码方案文件数、保护路径；无代码操作必须为空 diff                  |
| `code-review`：代码／方案审阅 | 校验后由已认证管理者审阅候选及证据                                           |
| `execution-auth`：执行授权    | 第一关通过后解锁，再次明确授权该候选进入执行阶段                             |
| `execute`：执行与归档         | 依据真实任务状态显示排队、运行、完成、失败或取消；批准本身不算执行成功       |

通过审批时意见可选；拒绝必须填写原因。真实决定同时绑定任务 `revision`、当前 `nodeId` 和 `round`，避免旧节点或上一轮表单推进新的关卡。已处理或尚未解锁的节点不能再次批准。实际操作者来自认证会话；当前控制台是单管理身份，两级流程不代表已经实现多人角色分权。演示样本中的负责人仍只是测试信息。

拒绝后，可以查看原决定并重新提交说明。重新发起只重开审批，不修改候选 diff，也不重新执行自动检查；原证据和旧轮次记录持续保留。取消任务同样保留流程、检查证据与决定；等待中的任务立即停止，已运行任务先记录取消请求，执行器确认后才结束。取消请求发出后不再允许用该租约提交提案或完成结果，也不表示撤销已经发生的外部操作。没有显式节点证据时，界面显示暂无证据或尚未接入，不从“已配置”推断检查已经通过。

### 键盘与窄屏

任务搜索框位于「全部任务」页面，可使用键盘聚焦。详情和创建表单使用原生对话框，支持 Escape 关闭与关闭后的焦点恢复；页签支持左右方向键、Home 和 End。页面有跳转到主要内容的入口及可见焦点样式，常规页面导航也会将焦点移到主要内容。任务筛选重绘后恢复对应控件的焦点，重复应用未变化的条件不会清空选择。

窄屏通过菜单按钮打开侧栏，任务详情与审批保留触控入口；流程画布根据可用宽度调整展示，并允许横向滚动，完整节点信息仍可访问。样式包含浅色、深色及 `prefers-reduced-motion` 适配。已有版本的交互验收范围见 [v3 验收记录](design/validation.md) 和 [v4 任务工作区记录](design/task-workspace-v4.md)。

## 3. 设计沿革与共用组件

### v11 持久管理接口

沿用既有视觉、图表和交互组件，将真实模式的操作接到同源 API。服务增加任务队列与租约、两级审批、配置覆盖、身份校验和持久审计；前端保留表单、筛选及明确的保存反馈。具体 AI 引擎仍需通过 Worker 协议另行接入，本轮不构成生产 Agent 或静态 Site 部署。

### v10 连接设置与操作记录

默认入口与标准托管构建都读取同源 API，未连接时保留真实状态，不预置任务或操作记录。顶部全局搜索、模式徽标与连接设置的数据来源切换移除，开发测试样本保留显式入口。

连接设置通过三项连接列表和默认收起的详情减少首屏信息量；管理服务连接与监控配置的验证状态分别说明。操作记录采用紧凑表格、展开详情、四类组合条件和每页 15 条分页，导出范围覆盖全部匹配结果。完整变更与验证状态见 [v10 记录](design/console-v10.md)。

### v9 表面与导航

共享静态面板采用无整圈描边的白色／深灰表面、14px 圆角与轻阴影。画布和侧栏使用相同底色，移除侧栏右线、分组线、底部顶线和选中项外框，分组通过间距组织。选中导航使用 `--nav-active` 底色、字重与图标色，悬停和键盘焦点仍有反馈。

该版本将首页统计带的分隔改为短、淡线条，标题、引擎、最近任务及列表图标去掉小方框描边；当时的连接来源选项使用浅色填充与左侧标识，v10 已用连接列表替代。Ghost 与图标按钮的悬停反馈使用底色和颜色，不增加外圈。

`ui.css` 定义共享表面与 `--line-soft` 轻分隔，`navigation.css` 处理页面框架，`dashboard.css` 和 `settings.css` 补充局部布局。普通 `--line` 没有全局设为透明；输入框、校验错误、表格行、审批流程节点、浮层／tooltip 和可见焦点保留功能所需的边界。完整变更与验证范围见 [v9 表面与侧栏记录](design/console-v9.md)。

### v8 报表与共用组件

各模块统一使用 `apps/console/public/ui.js` 的按钮、搜索、下拉框、状态、页签、空状态与 `uiMetric` 图标数据卡，以及 `ui.css` 的主题和交互样式。v8 在原有浅灰画布、轻边框和紧凑字阶上扩大报表区域，以语义图标标识指标、图表、问题类型与引擎；最近任务收为辅助区块。环形图与柱图由本地 SVG／CSS 绘制，没有新增图表运行时依赖。浅色、深色、可见焦点与减少动画偏好继续使用共用规则。

`interaction.js` 为重绘后的控件保留短暂点击反馈；实际结果仍由业务状态或提示确认，手动刷新明确报告成功／失败。报表聚合由纯函数 `analytics-model.js` 提供，图表下钻复用任务控制器，模块 CSS 负责布局。v8 的数据口径、交互与验收见 [报表首页记录](design/console-v8-review.md)；v7 的列表密度与重复筛选修复保留在 [历史记录](design/console-v7.md)。

v3 曾采用蓝灰色的实感玻璃工作台，借助高光、阴影和局部渐变区分运行概览、流程画布与审批请求。以下保留历史设计决策；当前外观由共用组件提供，两级审批状态和证据结构继续沿用。

| v3 设计决策        | 历史实现                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------- |

| 语义图标体系       | 导航、任务类型、Agent、质量验证、安全检查和审批节点使用不同 Lucide 图标；节点图标配有小范围渐变底座 |
| 流程作为视觉焦点   | 首页展示审批进展，审批中心使用可点选节点与连线，质量和安全检查并行呈现                              |

| 审批与证据同处     | 节点详情、负责人、审批意见、候选 diff、验证证据与历史记录可以在同一审批上下文中查看                 |

| 操作记录                                      | 服务端生成并持久保存，支持筛选、详情和公开字段导出               |
| 监控配置                                      | 真实模式服务端保存；演示模式保留本机草稿                         |
| Grafana 检查                                  | 检查允许来源的服务健康与 Prometheus 数据源 UID／名称，不查询指标 |
| 管理身份与 Worker 凭据                        | 已分离；管理会话为单身份模式，尚无多用户 RBAC                    |
| Agent 队列、租约、提案与回传协议              | 已实现；没有活跃 Worker 时任务保持等待                           |
| 具体 AI 执行器与远端仓库动作                  | 仓库没有预装实现，生产适配器及模型／仓库／CI 权限需另行配置      |
| Webhook、定时巡检、CI、自动回滚及熔断运行组件 | 尚未实现；现有配置字段不能作为已经运行的证据                     |
| 监控指标代理、嵌入面板和 Kubernetes 健康检查  | 尚未实现；外部 Grafana 页面承担实际指标查看                      |
| 状态刷新                                      | 真实模式在不打断输入时轮询，也可手动刷新；没有实时推送           |

`trigger` capability 表示可以接收并保存任务，不保证执行器在线。引擎状态依据最近认证 Worker 通信，配置存在不能替代连接证据；一次心跳也不能证明模型、仓库或集群健康。

连接实际系统时，将 Agent 拆成诊断／生成候选和授权执行两阶段，使用 [Worker 协议](agent-worker-api.md) 领取与回传；管理服务不会自行调用 AI、shell 或 GitHub。`create-issue`／`retry` 使用无代码变更的操作方案，和代码修改一样必须经过两级审批。

当前交付是可运行代码与本地联调，不表示已连接用户的生产 Agent、Grafana 或 Kubernetes。原私人 Site 仅能承载静态 UI，本轮没有将 Node API 部署到该 Site；实际使用请从部署的同源管理服务地址进入。

## 5. 开发、构建与验收

日常测试与构建命令：

```bash
npm install
npm test
npm run typecheck
npm run build
```

`npm test` 使用 Node 内置测试运行器。`typecheck` 检查 `packages/framework/src/**/*.ts` 的严格类型契约，当前不对浏览器 JavaScript 进行 TypeScript 检查。`build` 先运行该类型检查，再复制静态管理台到 `dist/`。

| 命令                                  | 产物或行为                                         |
| ------------------------------------- | -------------------------------------------------- |
| `npm run build:console`               | 将前端复制到 `dist/`，默认读取同源 API             |
| `npm run build:demo`                  | 仅用于显式开发测试，将虚构样本设为该构建的初始数据 |
| `npm run test:watch`                  | 监听测试文件变化并重新运行                         |
| `node apps/healing-hub/src/index.mjs` | 直接启动同源工作台、持久管理 API 与 Worker 接口    |

构建命令会重新生成 `dist/`。标准托管使用 `npm run build` 或 `npm run build:console`，默认请求同源 `/api/healing/snapshot`。静态产物只包含前端资源，不包含 Node 网关或执行器；未提供该 API 时保留未连接状态，不自动填充样本。需要实际任务与写入能力时，在同一来源运行持久管理 API。请通过 HTTP 服务打开模块页面，不直接双击 `index.html`。

### 显式启用开发测试样本

开发者可访问 [http://127.0.0.1:8787/?demo=1](http://127.0.0.1:8787/?demo=1)，或使用 `npm run build:demo` 生成单独的测试构建，以检查有数据的布局与模拟交互。两种方式都需要显式选择，不属于默认用户流程；普通连接设置不提供来源切换。

测试快照包含 48 条虚构任务：42 条已完成、3 条失败、1 条运行中、2 条待审阅，以及由样本任务生成的操作记录。任务时间根据打开页面的时间生成，覆盖最近七天。项目、文件、提交、检查结果、负责人和日志均为测试信息，不代表真实仓库执行或登录身份。显式测试状态保留来源说明，不能把样本显示成真实运行数据。

演示任务数据只保存在页面内存，重新加载测试入口会重新生成。「刷新」保留当前模拟快照。仅演示监控草稿按模式和项目保存到本机；真实模式读取服务端配置，不再采用浏览器中的历史 live 草稿作为配置覆盖。退出测试时使用普通入口及标准构建。
