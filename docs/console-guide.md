# Web 工作台使用与设计说明

`heal` 工作台用于查看任务、审阅候选变更及检查自愈系统的配置。当前交付包含可交互前端、同源只读配置网关和独立的内存演示数据；具体 Agent 执行器尚未接入。

## 1. 本地运行

要求 Node.js 18 或更新版本。在仓库根目录运行：

```bash
npm run dev
```

默认访问 [http://127.0.0.1:8787/](http://127.0.0.1:8787/)。`npm start` 使用同一个入口。网关与前端静态资源由同一服务提供；当前启动过程使用 Node 内置模块，运行工作台本身不依赖 Redis、MySQL、GitHub App 或第三方模型凭据。

可通过环境变量调整端口：

```bash
PORT=8790 npm run dev
```

默认监听 `127.0.0.1`，`HOST` 可显式覆盖监听地址。当前没有登录或 RBAC；跨机器部署需要另行提供访问控制。

### 查看交互演示

打开 [http://127.0.0.1:8787/?demo=1](http://127.0.0.1:8787/?demo=1)，或进入「连接设置」选择「交互演示」。页面会明确标记演示模式。

演示初始化时包含 48 条虚构任务：42 条已完成、3 条失败、1 条运行中、2 条待审阅；任务时间根据打开页面的时间生成，覆盖最近七天。数据包含类型错误、Lint、单元测试、依赖与文档等场景，示例中的文件、提交、检查结果与日志均不代表真实仓库执行记录。

演示数据只保存在页面内存。同一页面切换数据来源后可继续查看本次模拟结果；重新加载页面会重新生成数据。「刷新」在演示模式中保留当前模拟快照。主题偏好单独保存在浏览器本地存储。

### 读取项目配置

默认入口使用「真实管理服务」，请求同源 `GET /api/healing/snapshot`。真实模式的含义是读取当前网关，不表示 Agent 已经在线。

| 内容 | 优先读取 | 优先文件不存在时读取 |
| --- | --- | --- |
| 项目与执行策略 | `configs/healing-config.json` | `configs/healing-config.example.json` |
| 路由规则 | `configs/healing-rules.json` | `configs/healing-rules.example.json` |

需要自定义配置时可复制模板：

```bash
cp configs/healing-config.example.json configs/healing-config.json
cp configs/healing-rules.example.json configs/healing-rules.json
```

编辑文件后，在「连接设置」点击「刷新」。服务每次请求都会重新读取文件，配置与规则分别显示来源。实际文件存在但格式错误或无法读取时，服务返回明确错误；页面保留错误状态，不自动显示演示数据。当前没有 `.env` 加载或模板变量替换逻辑，`{{...}}` 占位符不会自动解析为凭据。

配置响应使用逐层字段白名单。模型 API key、GitHub 私钥、Webhook secret 等敏感字段不进入响应。完整规则导出、规则执行和配置写回不属于当前 API；允许输出的字段及错误结构见 [API 文档](console-api.md)。

## 2. 使用工作台

| 页面 | 可查看或操作的内容 |
| --- | --- |
| 工作台 | 按「需要你处理」「正在运行与排队」「需要关注」「最近完成」组织任务；待审阅项可展开少量 diff，再进入完整详情 |
| 全部任务 | 按任务名称、ID、类型、仓库、分支、文件或错误信息搜索，并组合状态及时间范围筛选 |
| 任务详情 | 切换「执行过程」「代码变更」「验证证据」「日志」，查看问题、修复候选与检查结果 |
| Agent 引擎 | 查看 `fast` / `complex` 路由、配置模型与引擎类型；当前统一显示未接入 |
| 路由规则 | 查看 `match` 与 `processor` 字段，演示模式可模拟切换规则开关 |
| 安全策略 | 查看保护路径、单次文件上限、检查命令、回滚与熔断配置 |
| 活动记录 | 查看当前数据来源的活动；可导出带模式标记的 JSON 文件 |
| 连接设置 | 切换演示与真实服务，检查配置来源、读取时间与连接错误 |

时间范围提供「今天」「近 7 天」「近 30 天」。筛选与趋势都按任务创建时间及 `Asia/Shanghai` 日历日期计算，包含当天，排除未来时间。成功率只计算 `completed / (completed + failed)`；运行、排队、取消和跳过的任务不进入分母。平均耗时仅取已完成或失败且有有效耗时的记录。没有可计算数据时显示 `—`。

### 演示操作的状态变化

| 操作 | 适用对象 | 结果 |
| --- | --- | --- |
| 发起巡检 | 演示模式，填写标题、类型、优先级和分支 | 新增 `pending` 手动任务，不会启动实际执行 |
| 取消任务 | `pending` 或 `running` | 改为 `cancelled` |
| 重新尝试 | `failed` 或 `cancelled` | 保留原记录，新建 `pending` 任务，并增加 `context.retryCount` |
| 批准方案 | `reviewState: pending` | 改为 `approved`，任务仍等待执行，不生成已完成结果 |
| 拒绝方案 | `reviewState: pending` | 改为 `rejected`，任务状态改为 `cancelled` |
| 切换路由规则 | 已存在的演示规则 | 更新内存中的 `enabled`，不写回配置文件 |

每次模拟操作会追加活动记录。审批使用单独的 `reviewState` 字段，原有 `TaskStatus` 的六种状态保持不变。

### 键盘与窄屏

`⌘ K` 或 `Ctrl K` 打开任务搜索。详情和创建表单使用原生对话框，支持 Escape 关闭与关闭后的焦点恢复；页签支持左右方向键、Home 和 End。页面有跳转到主要内容的入口及可见焦点样式。

窄屏通过菜单按钮打开侧栏，任务详情与行内审阅保留触控入口。样式包含浅色、深色及 `prefers-reduced-motion` 适配。桌面、390px 窄屏、审阅入口、主题与关键键盘导航已完成浏览器检查，详细范围见 [验收记录](design/validation.md)。

## 3. v2 设计说明

v2 将工作台组织为任务收件箱：打开页面先看到待审阅的修复、正在运行的任务及需要处理的失败。已完成记录保持紧凑；数据统计放在右侧窄栏，作为处理任务时的辅助信息。

| 设计决策 | 当前实现 |
| --- | --- |
| 任务优先的信息层级 | 待处理列表占主区域，审阅项直接展开 diff 片段，完整证据进入右侧详情 |
| 克制的视觉层次 | 暖白主画布、浅灰侧栏、石墨文字、细分隔线和小圆角；主按钮使用深色实底 |
| 用颜色表达状态 | 低饱和绿、黄、红分别用于完成、待审阅和失败；diff 用浅色底区分增删 |
| 减少仪表盘占位 | 不使用首屏成排 KPI 卡片或大幅渐变图表；保留窄栏数字与小型趋势图 |
| 可读的配置与证据 | 规则、策略和连接详情按字段排布；文件路径、命令、日志使用等宽字体 |
| 同一结构支持不同屏幕 | 桌面保留侧栏与摘要区，窄屏收起导航并调整内容排列；深色主题沿用相同布局 |

本版替代最初以统计卡片为主的视觉方向。设计文档中的较早色彩、材质和卡片设想应结合此处的 v2 更新阅读。前端采用浏览器 ES modules 与 CSS，未引入 React、组件库运行时或打包器。

## 4. 当前边界与后续对接

| 能力 | 当前状态 |
| --- | --- |
| Web 页面、任务搜索、筛选、详情与主题 | 已实现 |
| 演示任务、diff、Trace、证据、日志与模拟操作 | 已实现，仅页面内存 |
| 同源静态服务、配置读取、来源标记及敏感字段白名单 | 已实现 |
| 复用 `Task`、`TaskStatusInfo`、`Result` 的 JSON 契约 | 已实现；日期转为 ISO 字符串，UI 扩展字段独立定义 |
| EventHub、实际队列、事件路由执行 | 尚未接入 |
| Direct AI、ZCode 或其他具体 `WorkflowEngine` | 尚未实现或接入 |
| Webhook 接收、Cron 调度、GitHub App 仓库操作 | 尚未接入 |
| 真实触发、取消、重试、审批、规则写回 | 尚未接入；已列出的任务写接口返回 `501` |
| 安全检查、CI 验证、自动回滚与熔断执行 | 当前只展示策略配置 |
| 登录、RBAC、任务及审计持久化 | 尚未实现 |
| 实时推送、自动轮询任务状态 | 尚未实现，连接设置可手动刷新 |

因此，真实模式下任务和活动列表为空，写操作 capability 均为 `false`。引擎的 `configured` 表示找到配置；`implemented: false` 和 `status: unavailable` 如实表示没有连接执行器。界面中的工作空间名称与头像属于展示信息，不代表登录认证。

接入实际系统时，应先实现 `WorkflowEngine` 的执行、健康检查、取消与状态查询，并把任务结果投影到 `ConsoleTask` 契约；再接入队列、审计存储及有权限校验的写接口，按真实可用能力开放 capability。前端目前只对演示操作执行本地更新，真实写操作还需要对应的客户端请求逻辑。协议、路由及安全字段边界见 [API 文档](console-api.md)。

## 5. 开发、构建与验收

日常测试与构建命令：

```bash
npm install
npm test
npm run typecheck
npm run build
```

`npm test` 使用 Node 内置测试运行器。`typecheck` 检查 `packages/framework/src/**/*.ts` 的严格类型契约，当前不对浏览器 JavaScript 进行 TypeScript 检查。`build` 先运行该类型检查，再复制静态管理台到 `dist/`。

| 命令 | 产物或行为 |
| --- | --- |
| `npm run build:console` | 将前端复制到 `dist/`，默认读取同源 API |
| `npm run build:demo` | 将前端复制到 `dist/`，并明确设置默认演示模式 |
| `npm run test:watch` | 监听测试文件变化并重新运行 |
| `node apps/healing-hub/src/index.mjs` | 直接启动本地工作台与配置 API |

构建命令会重新生成 `dist/`。静态构建只包含前端资源，不包含 Node 网关或执行器；普通静态托管适合演示模式。真实模式需要在同一来源提供 `/api/healing/snapshot`。请通过 HTTP 服务打开模块页面，不直接双击 `index.html`。

截至本次文档更新，模型和 HTTP 集成测试共 40 项已通过，覆盖日期边界、统计口径、HTML 转义、模拟状态变更、配置投影与错误、未实现写接口，以及静态路径隔离。`npm run build`（包含严格 TypeScript 契约检查）和浏览器 JavaScript 语法检查已通过。浏览器已验证创建、取消、重试、批准、搜索、来源切换、连接失败、深色主题与 390px 审阅入口；详见 [验收记录](design/validation.md)。
